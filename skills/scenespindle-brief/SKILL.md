# SceneSpindle brief building

Read [the briefing specification](../../docs/BRIEFING_WORKFLOW.md), then only the relevant project/series context. Application automation is planned, not implemented; this skill can guide a native assistant's planning now.

Preserve the original request, exact script, approved cast and stated constraints. Infer low-impact defaults visibly. Resolve facts from available material before asking. Research only what the task benefits from; keep private content out of public queries.

When materially different creative directions remain, offer 2–3 options with a recommendation and one concise tradeoff each. Batch at most three questions; accept free text. A narrowly scoped edit should not reopen the whole creative brief. Missing required facts/assets remain blockers, not invented content.

Return a concise creative brief, assumptions/sources, unresolved decisions, workflow and task-specific prompts. Match actual renderer/provider capabilities. Let the user review the direction before expensive execution under the existing project gates. Improving a prompt does not authorize rendering, publishing, installation or expanding budgets.

Only consult [the toolbox index](../../docs/toolbox/README.md) when a specific supporting technique is needed. Do not load all upstream skills or copy their global instructions. Do not promise a perfect prompt or expose private reasoning.
